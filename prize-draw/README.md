## 검토한 문제와 변경 내용

### 1. 확률/등수 변경 후 설정 시그니처 불일치로 정지

기존 `signature()`는 확률이 포함된 `C.ranks`를 저장 원장과 비교했습니다. 한 번 기록이 생긴 뒤 설정을 바꾸면 `read()`가 실패했고, 초기화도 같은 읽기를 거쳐 복구가 막힐 수 있었습니다. 지적한 문제가 맞습니다.

새 버전에서는 **시그니처 비교와 원장 읽기를 모두 제거**했습니다. 각 버튼 요청에서 현재의 등수·확률·경품명을 복사해 검증하고 그 값으로 추첨합니다. 확률, 등수 id/이름, 경품명을 바꿔도 기존 설정/기록과 비교하지 않습니다. 팝업을 연 후 설정을 바꿔도 버튼을 누르는 시점의 설정으로 추첨하며, 룰렛의 칸 이름도 실제 결과와 함께 갱신합니다.

확률은 0~100의 유한한 숫자이고 합계가 100이어야 하며 룰렛은 3개 등수를 사용합니다. 잘못된 설정은 해당 요청에만 안내합니다. 유효한 설정으로 수정하면 다음 요청이나 팝업의 **다시 확인**으로 이용할 수 있고, 스토리지 초기화나 오류 해제를 위한 앱 재시작은 필요 없습니다. 배포 파일의 설정을 바꿀 때는 기존처럼 수정한 ZIP을 앱에 업데이트해야 합니다.

### 2. 저장 지연/재조회 불일치 한 번에 전체 행사 중지

기존 저장 요청 타임아웃/재조회 불일치는 `stopped = true`를 설정했고 앱 재시작 전까지 모든 참여자를 막았습니다. 이 역시 지적한 문제가 맞습니다.

새 버전은 **저장 요청·저장 대기 큐·재조회·저장 타임아웃·전역 오류 정지 상태를 모두 제거**했습니다. 따라서 저장 지연·저장 용량·구버전 원장의 손상 여부가 추첨 경로에 영향을 주지 않습니다. 추첨/팝업 생성/화면 전송의 오류는 해당 요청 범위에서 처리합니다. 다른 참여자는 계속 이용할 수 있으며 실패한 참여자는 **다시 확인** 또는 팝업을 닫고 재접촉하여 재시도할 수 있습니다.

화면 전송만 실패한 경우 열린 팝업의 현재 결과를 잠시 보관하여 `ready`/`retry` 응답으로 같은 결과를 다시 보냅니다. 이때 재추첨하지 않습니다. 이는 영구 당첨 기록이 아니라 현재 팝업의 응답 상태이며, 닫기/이탈/앱 종료 시 폐기됩니다. 과거 결과를 쌓아두는 배열·계정별 당첨 원장은 없습니다.

앱을 수동으로 중지하는 `paused`만 남아 있으며 **오류가 이 값을 변경하지 않습니다.** `!경품시작` 또는 `!경품재개`는 설정 검증/스토리지와 독립적으로 동작합니다. 앱이 정상 실행 중인 상태의 오류 복구 구조이며 ZEP 자체 장애나 앱 파일 미설치까지 방지하는 보장은 아닙니다.

## 추첨 규칙

| 등수 | 매 추첨 확률 |
|---|---:|
| 1등 | 5% |
| 2등 | 10% |
| 3등 | 85% |

재고·총수량·일일 한도는 없습니다. 팝업 확률 고지 문구는 표시하지 않으며 실제 확률만 위 설정으로 적용합니다. 룰렛의 3칸은 같은 크기의 디자인이고 면적이 실제 확률을 뜻하지 않습니다. 유한한 추첨 횟수의 실제 발생 비율은 설정값과 다를 수 있습니다.

**로그인/비로그인 모두 참여 가능하며 반복 참여 제한이 없습니다.** 한 팝업에서는 중복 클릭을 막고 한 번만 추첨합니다. 닫고 다시 오브젝트를 이용하면 새 추첨이 가능합니다. 이메일 해시·게스트 방문 식별값·당첨번호·당첨시각·통계를 저장하거나 복원하지 않습니다. 현장 확인 후 경품 지급 여부는 운영자가 직접 관리해야 합니다.

## 맵 입장 시 자동 팝업

기본값 `autoOpenOnJoin: true`로 지정된 `drawMapId` 맵에 입장할 때마다 룰렛 팝업을 자동 표시합니다. 로그인·게스트 모두 동일하며, 입장만으로 추첨하지 않고 팝업의 **룰렛 돌리기** 버튼을 눌러야 결과를 정합니다.

열린 팝업이 있으면 입장 이벤트나 오브젝트 접촉이 겹쳐도 새 창을 중복 생성하지 않습니다. 팝업을 닫은 뒤에는 기존 오브젝트로 다시 열 수 있습니다. 맵을 나갔다 다시 들어오면 팝업을 다시 표시합니다. 다른 맵이나 맵 ID 미설정 상태에서는 자동 표시하지 않습니다. 자동 표시를 끄려면 `autoOpenOnJoin: false`로 설정하면 됩니다.

## 설치·업데이트

1. ZIP을 내려받아 압축을 풉니다. 별도의 ZEP 사이드바 앱으로 설치하거나 기존 경품 앱을 업데이트합니다. 다른 앱을 덮어쓰지 마세요.
2. 처음 설치하는 경우 `drawMapId`를 기본 미설정 값으로 두고 먼저 앱을 설치합니다. 추첨 맵에서 관리자 계정으로 `!경품맵확인`을 입력합니다.
3. 표시된 실제 `drawMapId`를 `main.js` 상단에 복사합니다. 단축 링크 `https://zep.us/play/rbbq9p`에서 내부 맵 ID를 추정하지 마세요. 기존 앱 업데이트에서는 사용하던 실제 맵 ID를 유지하면 됩니다.
4. 닫은 팝업을 다시 열 수 있는 오브젝트가 필요하면 맵 에디터 → **오브젝트설치 → 개발자 기능 → ZEP Script 상호작용**으로 원하는 오브젝트를 배치합니다.

   | 오브젝트 설정 | 입력값 |
   |---|---|
   | Number | `1001` |
   | Value | `prize_draw` |

   기본 `interactionMode: "editor"`, `objectNumber`, `objectValue`와 일치시킵니다. 이 방식은 오브젝트 접촉 이벤트를 사용합니다.
5. 실제 경품명을 `prizeNames`에서 설정합니다. 확률/등수는 `ranks`에서 수정합니다. 3개 등수, 확률 합계 100을 유지하세요.
6. **`main.js`와 `prize-draw.html` 두 파일만 ZIP 최상위**에 넣어 같은 앱을 업데이트합니다. CSV용 `prize-export.html`은 더 이상 필요 없습니다.
7. 실제 ZEP 맵에서 입장 → 자동 팝업 → 버튼 → 약 3초 회전 → 등수/경품명과 콘페티, 다시 확인과 관리자 명령을 확인하세요.

```sh
python3 -c 'from zipfile import ZipFile; z=ZipFile("upload.zip","w"); z.write("main.js"); z.write("prize-draw.html"); z.close()'
```

구버전 당첨 기록이 앱 스토리지에 남아 있어도 새 버전은 **읽거나 참조하지 않습니다.** 스토리지 전체를 강제로 지우거나 다른 앱의 데이터를 덮어쓰지도 않습니다. 따라서 업데이트 전에 원장 초기화나 데이터 마이그레이션을 할 필요가 없습니다. 과거 저장 데이터의 물리적인 삭제를 수행하는 기능은 이 무저장 버전에 포함하지 않습니다.

고급 연결: `interactionMode: "key"`와 `objectKey`, 또는 `interactionMode: "position"`과 `objectPosition: {layer:3,x:10,y:10}`을 사용하면 이전 F 상호작용 방식으로 연결할 수 있습니다. 상단 오브젝트의 레이어는 5입니다.

## 관리자 명령

관리자/소유자(`role >= 3000`)만 사용할 수 있습니다. 결과는 요청한 관리자에게 개인 메시지로 표시합니다.

| 명령 | 기능 |
|---|---|
| `!경품맵확인` | 실제 맵/스페이스 ID 확인. 미설정 상태에서도 가능 |
| `!경품현황` | 현재 진행/수동 중지 상태와 확률 설정 확인. 당첨 통계 없음 |
| `!경품중지` | 현재 실행 인스턴스의 신규 추첨을 수동 중지 |
| `!경품시작` | 수동 중지 해제. 오류 안내 중인 팝업도 다시 확인 |
| `!경품재개` | `!경품시작`과 동일. 초기화 없이 재개 |
| `!경품도움말` | 이용 방법 및 현재 명령 안내 |

`!당첨목록`, `!당첨내보내기`, `!경품초기화`는 제거된 기능임을 안내하고 데이터를 생성/수정하지 않습니다. 수동 중지 상태는 메모리에서만 유지하므로 앱 재시작 시 진행 상태로 시작합니다. 여러 실행 인스턴스의 수동 중지는 서로 공유하지 않습니다. 중지 전에 이미 확정된 결과의 3초 화면 연출은 끝까지 표시될 수 있습니다.

## 모바일·화면

2026 용봉학술제 AICOSS 이벤트 타이틀과 푸른색 방사형 배경, 3분할 입체 룰렛을 유지합니다. 상단 AICOSS LUCKY ROULETTE, 기존 안내 문구, 확률 고지는 표시하지 않습니다. 현재 버전에서는 당첨번호/날짜 표시도 제거했습니다.

작은 세로 화면은 실제 남은 공간에 맞춰 룰렛 크기를 조정하고 가로 화면은 2열로 배치합니다. 320×568부터 태블릿·가로 화면까지 검증합니다. 오류 안내에는 **다시 확인** 버튼을 표시합니다. 설정이 바로잡히거나 수동 중지가 풀리면 재시도할 수 있습니다. 기기의 모션 감소 설정에서는 긴 회전을 생략합니다.

브라우저 미리보기는 `prize-draw.html?preview=1`에서 버튼을 누르면 샘플 2등을 표시합니다. 실제 ZEP 원장이나 경품 지급 기록은 만들지 않습니다. 로컬 파일 열기가 제한되면 `python3 -m http.server 8000` 실행 후 `http://localhost:8000/prize-draw.html?preview=1`로 접속하세요. 외부 이미지/폰트/JS 라이브러리를 요청하지 않습니다.
