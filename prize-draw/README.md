# 2026 용봉학술제 AICOSS 이벤트 — 같은 브라우저 1회 참여 룰렛

맵에 입장하면 개인 팝업이 자동으로 열립니다. **같은 기기·같은 브라우저/프로필에서 행사당 한 번** 참여하고, 이후에는 기존 당첨 등수를 표시합니다. 로그인과 게스트를 구분하지 않으며 같은 브라우저에서 계정을 바꿔도 이미 참여한 결과를 보여줍니다.

- [최초 참여 PC 화면](https://github.com/junho3789/ZEP/blob/main/prize-draw/previews/desktop.jpg)
- [재접속 모바일 화면](https://github.com/junho3789/ZEP/blob/main/prize-draw/previews/mobile.jpg)

## 참여 흐름

1. 처음 입장하면 브라우저에 해당 행사 기록이 있는지 확인하고 `룰렛 돌리기`를 활성화합니다.
2. 버튼을 누르면 먼저 참여 시작 예약을 브라우저에 저장하고 서버 스크립트에 추첨을 요청합니다.
3. 서버는 설정 확률로 등수를 정합니다. 받은 **등수·경품명·룰렛 칸 정보를 브라우저에 저장한 다음** 약 3초 감속 회전을 재생합니다.
4. 재접속/새로고침/팝업 재열기 시 기존 등수를 복원하고 재추첨 버튼은 비활성화합니다. 이전 결과는 회전/콘페티를 다시 재생하지 않고 바로 표시합니다.

서버/ZEP 스토리지·외부 DB·IP 조회는 사용하지 않습니다. 관리자 당첨 원장이나 CSV 기능도 없습니다. 재접속 복구를 위해 **참여자의 브라우저 내부 IndexedDB에 최소 결과를 저장하는 점**은 이전 무저장 버전과 다릅니다. 이메일·IP·닉네임은 저장하지 않습니다. 서버에는 열린 팝업의 응답만 잠시 보관하고 닫으면 폐기합니다.

## 제한의 범위

이 방식은 **브라우저에 남아 있는 기록을 기준으로 한 재참여 방지**입니다. 동일인 인증이나 변조 방지 시스템은 아닙니다.

- 시크릿 모드, 사이트 데이터 삭제, 다른 브라우저/프로필, 다른 기기로는 다시 참여할 수 있습니다.
- 같은 브라우저/프로필을 여러 사람이 공유하면 첫 참여 결과를 함께 보게 됩니다.
- 기록은 같은 브라우저의 ZEP 위젯 저장소가 유지될 때 복구됩니다. 브라우저 정책에 의한 데이터 삭제, 저장소 분리, 위젯 제공 출처 변경 시 유지되지 않을 수 있습니다.
- 개발자 도구로 브라우저 기록을 수정하는 행위를 막지는 못하며, 지급 여부는 현장에서 확인해야 합니다.
- 같은 브라우저의 여러 탭은 **IndexedDB 읽기/쓰기 트랜잭션**으로 참여 확인과 예약을 한 번에 처리합니다. 결과 기록도 같은 방식으로 완료한 뒤 화면에 표시합니다. 탭 간 결과 갱신은 BroadcastChannel로 알리며 미지원 환경은 주기적으로 해당 기록을 확인합니다. IndexedDB를 사용할 수 없으면 저장 없이 추첨하지 않고 안내합니다.

**실제 ZEP에서 저장소 접근과 재입장 복구를 반드시 확인하세요.** 로컬 브라우저 검증은 실제 ZEP iframe의 쿠키/저장소 권한을 보장하지 않습니다. 저장소 차단이나 용량 부족 시 기록 없이 추첨하도록 우회하지 않고 해당 사용자에게 안내합니다. 다른 참여자를 막거나 앱 전체를 오류 상태로 정지시키지는 않습니다.

## 행사 구분과 설정

`main.js` 상단의 `participationKey`는 현재 행사를 식별하는 고정 값입니다.

```javascript
participationKey: "aicoss-yongbong-2026-v1",
```

실제 저장 키는 이 값과 런타임 스페이스/맵 ID를 결합합니다. **같은 행사 운영 중에는 이 값과 맵을 유지하세요.** 확률/경품명/화면 업데이트만으로 참여 제한을 초기화하지 않습니다. 새 행사에서 다시 참여하게 하려면 새 `participationKey`를 지정합니다. 맵 ID나 브라우저 저장소 출처가 바뀌면 별도 기록으로 처리될 수 있습니다.

기존 무저장 버전에서 이미 추첨한 사람의 과거 기록은 존재하지 않으므로 소급해서 차단하거나 복원할 수 없습니다. 이 버전을 적용한 이후의 첫 참여부터 기록합니다.

## 추첨 확률과 화면

| 등수 | 확률 |
|---|---:|
| 1등 | 5% |
| 2등 | 10% |
| 3등 | 85% |

동일한 크기의 3분할 룰렛을 사용하며 면적이 실제 확률을 뜻하지는 않습니다. 확률 고지와 이전에 삭제한 안내 문구는 화면에 표시하지 않습니다. 상단 행사 타이틀과 푸른색 테마, 약 3초 감속, 당첨 후 콘페티, 모바일 세로/가로 반응형을 유지합니다. 모션 감소 설정에서는 긴 회전을 생략합니다.

등수는 서버 스크립트에서 결정하며 모바일/PC·로그인/게스트 여부를 확률 계산에 사용하지 않습니다. `ranks`는 3개, 확률 합계는 100이어야 합니다. 확률/등수/경품 설정 변경은 다음 신규 참여자부터 적용합니다. 기존 참여자의 결과는 브라우저에 저장된 당시 등수/경품명으로 표시합니다.

## 오류와 재시도

- **서버가 완료된 당첨이 없다고 명시한 오류**만 현재 팝업의 참여 예약을 해제합니다. 설정을 수정하거나 중지가 해제된 뒤 `다시 확인`으로 진행할 수 있습니다.
- 결과 저장에 실패하면 당첨 연출을 하지 않고, 같은 팝업에서 저장 재시도를 제공합니다. 새 난수를 요청하지 않습니다.
- 추첨 결과가 브라우저에 저장된 뒤라면 회전 중 창을 닫아도 재입장 시 같은 결과를 바로 복구합니다.
- **추첨 시작 요청 직후 결과를 받기 전에 창/앱을 종료하면** `pending`만 남아 당첨 결과를 복구하지 못할 수 있습니다. 중복 참여를 허용하지 않도록 자동 만료/자동 삭제/임의 재추첨은 하지 않고 현장 운영자 확인을 안내합니다. 서버 원장이 없는 방식의 한계입니다.
- 저장 기록이 손상되었을 때도 미참여로 간주하거나 자동 덮어쓰지 않습니다. 한 사용자의 저장소 문제로 전체 행사를 정지시키지는 않습니다.

## 설치·업데이트

1. ZIP을 내려받아 압축을 풉니다. 기존 경품 앱을 업데이트하거나 별도 사이드바 앱으로 설치합니다.
2. 처음 설치할 때는 미설정 `drawMapId`로 앱을 설치한 뒤 추첨할 맵에서 관리자 `!경품맵확인`으로 런타임 맵 ID를 확인합니다. 단축 URL에서 맵 ID를 추정하지 마세요.
3. `main.js`에 실제 `drawMapId`, 유지할 `participationKey`, 경품명(`prizeNames`)을 설정합니다. 입장 팝업은 `autoOpenOnJoin: true`입니다.
4. 닫은 팝업을 오브젝트로 다시 열려면 맵 에디터 → 오브젝트설치 → 개발자 기능 → **ZEP Script 상호작용** 오브젝트를 설치하고 **Number `1001` / Value `prize_draw`**를 지정합니다.
5. **`main.js`와 `prize-draw.html`을 반드시 함께 ZIP 최상위에 넣어** 같은 앱을 업데이트합니다. 브라우저 참여 예약 토큰을 주고받으므로 예전 JS/HTML을 섞지 마세요.
6. 실제 ZEP에서 최초 참여 → 결과 표시 → 팝업 닫기 → 맵 재입장 → 기존 결과 표시를 확인하세요. 모바일에서도 동일하게 확인해야 합니다.

```sh
python3 -c 'from zipfile import ZipFile; z=ZipFile("upload.zip","w"); z.write("main.js"); z.write("prize-draw.html"); z.close()'
```

고급 오브젝트 연결은 `interactionMode: "key"`+`objectKey` 또는 `interactionMode: "position"`+`objectPosition`을 지원합니다. 기본 개발자 상호작용 방식에서는 key나 좌표 설정이 필요 없습니다. 추첨 기록을 ZEP 스토리지에서 읽지 않으므로 구버전 원장 초기화도 필요 없습니다.

## 관리자 명령

관리자/소유자(`role >= 3000`)만 사용합니다. 브라우저별 기록을 관리자에게 수집하거나 목록으로 제공하지 않습니다.

| 명령 | 기능 |
|---|---|
| `!경품맵확인` | 런타임 맵/스페이스 ID 확인 |
| `!경품현황` | 진행 상태와 확률 확인. 브라우저별 참여 기록/통계는 조회하지 않음 |
| `!경품중지` | 현재 실행 인스턴스의 신규 추첨 수동 중지 |
| `!경품시작`, `!경품재개` | 수동 중지 해제, 오류 안내 팝업 재확인 |
| `!경품도움말` | 사용 안내 |

`!경품초기화`, `!당첨목록`, `!당첨내보내기`는 제거된 기능을 안내할 뿐 데이터를 만들거나 지우지 않습니다. 관리자 재개는 브라우저 참여 기록을 초기화하지 않습니다. 중지 중에도 저장된 기존 결과는 확인할 수 있습니다. 앱 재시작 시 수동 중지는 해제되지만 브라우저 참여 기록은 사이트 데이터가 유지되는 동안 보존됩니다.

## 미리보기 및 검증

`prize-draw.html?preview=1`을 브라우저에서 열면 샘플 2등으로 확인할 수 있습니다. 미리보기는 운영과 다른 저장 키를 사용하며 미리보기에서도 새로고침 시 결과를 복구합니다. 운영 행사 키의 실제 참여 기록은 건드리지 않습니다.

핵심 서버 테스트(외부 패키지 불필요):

```sh
node tests/prize-draw.test.cjs
```

24개 테스트: ZEP 저장소 접근 0회, 확률/경계, 로그인·게스트 동일 처리, 설정 변경·요청 오류 격리, 관리자 중지/재개, 오브젝트/입장 자동 팝업, 브라우저 행사 키와 예약 토큰 전달 등. 서버 테스트 모형 자체는 브라우저 저장소를 구현하지 않으므로 기기별 중복 제한은 아래 브라우저 검증에서 확인합니다.

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/widget.test.cjs
```

Chromium 검증: 재접속/새 탭 결과 복구, 연출 전 저장, 회전 중 종료 복구, 중복 버튼/동시 탭, 요청 직후 종료 시 재추첨 차단, 저장 차단/용량 오류·손상 기록의 처리, 새 행사 구분, 3개 등수 정지 각도, 7가지 모바일·태블릿 크기와 안전한 텍스트 표시. `CHROMIUM_PATH`로 기존 Chromium을 지정할 수 있습니다.
