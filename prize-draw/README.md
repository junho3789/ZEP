맵의 **ZEP Script 상호작용 오브젝트**로 개인 팝업을 열고, **룰렛 돌리기** 버튼을 누르면 약 3초간 감속 회전한 뒤 당첨 등수·경품명·당첨번호를 표시합니다. 회전 종료 후 위에서 콘페티가 떨어집니다.

## 현재 추첨 규칙

| 등수 | 매 추첨 확률 |
|---|---:|
| 1등 | 5% |
| 2등 | 10% |
| 3등 | 15% |
| 4등 | 20% |
| 5등 | 50% |

**경품 재고, 전체 경품 수량, 일일 당첨 한도는 없습니다.** 이전 버전의 1,000개/등수별 수량/하루 제한은 제거했습니다. 매 신규 추첨에서 위 확률만 사용하며 이전 당첨 수량과 날짜에 따라 확률을 바꾸지 않습니다. 실제 발생 비율은 유한한 추첨 횟수에서 표의 값과 다를 수 있습니다.

룰렛판은 디자인 요청에 따라 **같은 크기의 5칸**입니다. 시각적인 면적이 당첨 확률을 뜻하지 않습니다. 요청에 따라 팝업에는 확률 고지 문구를 표시하지 않으며, 이 문서와 관리자 현황에서만 확률을 확인할 수 있습니다. 서버 스크립트가 결과를 정하고 ZEP 저장소 재조회에 성공한 뒤에만 화면으로 전송하며, 회전판은 그 등수가 포인터에 오도록 정확히 멈춥니다. 버튼 클릭 뒤 저장 응답을 받은 시점부터 약 3초 회전합니다. 모션 감소 설정에서는 회전을 생략합니다.

**비로그인 게스트도 참여할 수 있습니다.** 로그인 계정은 기존 이메일 해시 키를 유지하여 회차당 한 번 당첨되고, 게스트(또는 이메일 해시를 확인할 수 없는 참여자)는 서버가 발급한 방문 식별값으로 현재 방문 중 한 번 당첨됩니다. 게스트가 팝업을 닫았다 다시 열면 같은 결과를 복구합니다.

게스트 방문 식별값은 클라이언트가 제출하지 않으며 현재 실행 중인 앱의 메모리에서 관리합니다. **맵 이탈/재입장, 새로고침, 앱 재시작, 다른 기기에서는 새 방문으로 처리될 수 있어 동일인 중복 참여를 계속 막을 수는 없습니다.** 엄격한 동일인 1회 제한은 로그인 또는 별도의 검증된 참여 코드가 필요합니다. 게스트에게 관리자 권한은 부여하지 않습니다.

팝업 열기만으로는 추첨하거나 기록하지 않습니다. 로그인 계정은 닫기·재접속·재시작 후에도 기존 당첨 결과를 복구하며, 이미 당첨된 참여자에게는 돌리기 버튼을 활성화하지 않습니다.

## 설치 및 업데이트

1. ZIP을 내려받아 압축을 풉니다. ZEP에 별도의 사이드바 앱으로 설치합니다. 다른 코인·스탬프 앱을 덮어쓰지 마세요.
2. 먼저 `drawMapId`를 기본 미설정 값으로 둔 채 앱을 업로드·설치합니다. 실제 추첨 맵에서 관리자/소유자 계정으로 **`!경품맵확인`**을 입력합니다.
3. 개인 메시지에 나온 `drawMapId: "실제값"`을 `main.js` 상단에 복사합니다. `https://zep.us/play/rbbq9p` 같은 단축 링크에서 내부 맵 ID를 추정하지 마세요. `spaceHashID`와도 구별해야 합니다.
4. 맵 에디터 → **오브젝트설치 → 개발자 기능 → ZEP Script 상호작용**을 선택하여 배치하고 아래 값을 저장합니다.

   | 오브젝트 설정 | 값 |
   |---|---|
   | Number | `1001` |
   | Value | `prize_draw` |

   기본 코드의 `interactionMode: "editor"`, `objectNumber: "1001"`, `objectValue: "prize_draw"`와 일치시킵니다. 이 기본 방식에는 key나 좌표가 필요 없습니다. 오브젝트는 스크립트가 자동 생성하지 않으며 맵 에디터에서 배치합니다. 오브젝트에 접촉하면 팝업이 열립니다.
5. 실제 경품명은 `prizeNames`에서 `rank1: "실제 경품명"`처럼 설정합니다. 기본은 `1등 경품` 같은 임시 명칭입니다.
6. **`main.js`, `prize-draw.html`, `prize-export.html` 세 파일을 모두 ZIP 최상위에 넣어** 같은 앱을 업데이트합니다. HTML을 빠뜨리면 해당 팝업을 열 수 없습니다. README와 tests는 ZEP 실행에 필요 없습니다.
7. 테스트 스페이스에서 오브젝트 → 팝업 → 버튼 → 당첨 결과, 관리자 명령과 CSV를 확인한 뒤 운영하세요. 실제 ZEP 설치/모바일 입력/저장 지속성은 별도 확인이 필요합니다.

```sh
python3 -c 'from zipfile import ZipFile; z=ZipFile("upload.zip","w"); [z.write(f) for f in ["main.js","prize-draw.html","prize-export.html"]]; z.close()'
```

### 이전 재고형 버전에서 이어서 사용

`eventId`, `drawMapId`, 등수 id/이름/순서를 기존과 동일하게 유지하면 이전 v1 원장을 읽어 확률형 v2로 이어받습니다. 당첨 계정·당첨번호·회차·중지 상태를 유지하며, 기존 당첨자도 같은 회차에서는 다시 당첨되지 않습니다. 읽기만 할 때는 저장하지 않고 다음 추첨/관리자 상태 저장 때 v2 형식으로 기록합니다. 이전 총수량/일일 한도는 더 이상 적용하지 않습니다. 업데이트 전 CSV로 기존 원장을 별도 보관하세요.

v2 원장이 생성된 뒤 이벤트/맵/등수/확률을 바꾸면 설정 불일치로 추첨을 중지합니다. 정상 원장을 자동 삭제하지 않습니다. 기존 설정으로 되돌리거나 새 앱/새 스토리지로 다음 이벤트를 시작하세요. 경품 표시명은 별도 설정이라 변경 가능하지만 과거 당첨 결과/CSV도 현재 표시명으로 보입니다.

## 관리자 채팅 명령

관리자/소유자(`role >= 3000`) 전용입니다. 운영 명령은 지정된 추첨 맵에서 입력하고 결과는 해당 관리자에게만 표시합니다. 맵 확인은 미설정 상태에서도 가능합니다.

| 명령어 | 기능 |
|---|---|
| `!경품도움말` | 사용 안내 |
| `!경품맵확인` | 현재 런타임 맵/스페이스 ID 확인, 저장 데이터 변경 없음 |
| `!경품현황` | 확률·누적/오늘 당첨 통계·회차·진행 상태 확인. 통계는 제한이 아님 |
| `!당첨목록 1` | 현재 회차 당첨 원장 조회. 페이지당 10명, 숫자로 페이지 변경 |
| `!당첨내보내기` | 현재 회차 당첨 목록을 CSV로 다운로드 |
| `!경품중지` | 추첨 중지 및 상태 저장 |
| `!경품시작` | 추첨 재개 및 상태 저장 |
| `!경품초기화` | 중지 상태에서 60초 유효 확인 코드 발급 |
| `!경품초기화 확인코드` | 코드 확인 후 당첨 기록/통계/계정별 참여 제한 초기화 |

`!추첨`이나 사이드바 클릭은 오브젝트 이용 안내만 표시하며 직접 추첨하지 않습니다. Q 키 추첨도 없습니다.

### 새 회차 초기화

```text
!경품중지
!당첨내보내기
!경품초기화
!경품초기화 발급받은코드
!경품현황
!경품시작
```

초기화는 **현재 회차 원장을 삭제**하므로 필요한 목록을 먼저 다운로드하세요. 코드는 발급받은 관리자만 60초 안에 한 번 사용 가능하며 원장/진행 상태 변경이나 앱 재시작 시 무효입니다. 확인 코드 발급만으로 기록을 지우지 않습니다. 확률 설정은 유지하고 회차 R1 → R2를 증가시켜 이전 당첨번호와 구별합니다. 초기화 후에도 중지 상태이므로 `!경품시작`으로 재개합니다. 새 회차에서는 이전 당첨자도 다시 참여할 수 있습니다.

## CSV 문서 다운로드

`!당첨내보내기` → 관리자 팝업 → **CSV 다운로드**. 엑셀/스프레드시트에서 열 수 있는 UTF-8 BOM 파일입니다. 이벤트, 회차, 순번, 당첨번호, 등수, 경품명, 한국시간 당첨일/시각, 참여자 식별값과 참여 유형(로그인 계정/게스트)을 포함합니다. 로그인 참여자의 식별값은 기존 이메일 해시, 게스트는 서버 발급 방문 식별값입니다. 닉네임·이메일 원문은 저장하지 않아 포함하지 않습니다.

명령 실행 시점의 현재 회차 전체를 내보내며 이후 당첨 건은 재조회해야 합니다. 빈 목록도 열 제목이 있는 CSV로 받을 수 있습니다. 다운로드 제한 시 **내용 복사** 또는 **CSV 원문 보기**에서 직접 복사해 UTF-8 `.csv`로 저장하세요. 삭제된 이전 회차는 복구하지 못합니다. 파일은 관리자 브라우저에서 생성하며 외부 DB/서버/GitHub로 실제 원장을 전송하지 않습니다.

## 모바일 반응형 및 표시 문구

팝업 높이와 실제 남은 공간을 계산하여 룰렛 지름을 자동 조정합니다. 작은 세로 화면에서는 타이틀/룰렛/버튼/결과가 화면에 들어가도록 줄이고, 가로 화면에서는 2열로 배치합니다. 당첨 후 불필요한 비활성 돌리기 버튼은 숨겨 결과 영역과 룰렛 공간을 확보합니다. 브라우저 높이 변경/화면 회전에도 다시 계산하고, 예상보다 내용이 길어지면 카드 내부 스크롤로 접근할 수 있습니다.

요청에 따라 상단 `AICOSS LUCKY ROULETTE`, `1등부터 5등까지, 나의 경품은 무엇일까요?`, 하단 `회차당 계정별 한 번의 행운 · 당첨 후 운영 안내에 따라 경품을 수령하세요.`, 팝업 확률 고지 문구를 삭제했습니다. **행사 타이틀과 중앙 AICOSS 허브는 유지**합니다. 실제 추첨 확률과 재고/일일 한도 없음 규칙은 바꾸지 않았습니다.

## 디자인 및 미리보기

상단 타이틀은 **2026 용봉학술제 AICOSS 이벤트**입니다. 첨부 참고 이미지의 방사형 배경·원형 입체 테두리·장식 전구·중앙 포인터 구성을 푸른색으로 재구성했습니다. [AICOSS 홈페이지/사업단 로고](https://www.aicoss.kr/www/introduce/logo)의 파랑 계열을 참고했으며 공식 색상 규격을 인증한 것은 아닙니다. 외부 폰트·이미지·JS 요청 없이 HTML/CSS/SVG/Canvas로 동작합니다.

브라우저에서 `prize-draw.html?preview=1`을 열고 룰렛 돌리기를 누르면 샘플 2등 결과를 볼 수 있습니다. 실제 ZEP 기록을 만들지 않는 디자인 미리보기입니다. ZEP iframe 안에서는 미리보기 분기가 실행되지 않습니다. 로컬 파일 열기가 제한되면 폴더에서 `python3 -m http.server 8000`을 실행하고 `http://localhost:8000/prize-draw.html?preview=1`로 접속하세요.

고급 옵션: 이전 F 상호작용 연결을 유지하려면 `interactionMode: "key"`와 `objectKey`, 또는 `interactionMode: "position"`과 `objectPosition: {layer:3,x:10,y:10}`을 지정합니다. 상단 오브젝트 레이어는 5입니다. 기본 개발자 오브젝트 방식에는 필요 없습니다.

## 저장 및 운영 범위

외부 DB 없이 ZEP `App.getStorage(callback)`/`App.setStorage(string)`를 사용합니다. 원장 키는 `zepPrizeDrawV1`을 유지하며 스토리지의 다른 최상위 키는 보존합니다. 요청을 큐로 직렬 처리하고 쓰기 후 원장이 재조회에서 일치해야 당첨 결과를 보냅니다. 위젯에서 등수/결과를 임의 제출해도 무시하며 정상 오브젝트로 열린 자기 팝업의 버튼만 추첨 요청을 보낼 수 있습니다.

**추첨 맵 하나·실행 인스턴스 하나·앱 설치 하나**로 운영하세요. 공식 저장 API에는 원자적 비교 갱신/분산 잠금/영구 저장 완료 확인이 명시되어 있지 않아, 여러 맵·채널·서버 인스턴스의 동시 쓰기를 보장하지 못합니다. 맵 ID 차단은 같은 맵의 중복 실행까지 감지하지 못합니다. 서버 이전/종료 시 새 처리를 멈추지만 실행 중첩을 원자적으로 제어하지는 못합니다.

팝업을 닫거나 맵을 나가도 이미 제출한 버튼 요청은 완료될 수 있습니다. 저장된 결과는 다음 방문에서 복구합니다. 저장 오류/응답 지연/원장 손상/설정 불일치 시 임의 재추첨·초기화를 하지 않고 인스턴스를 중지하므로 원인을 해결하고 재시작하세요.

재고나 일일 인원 제한은 없지만 **스토리지 용량 자체가 무한하지는 않습니다.** `maxStorageBytes: 200000`은 이 앱의 기록 크기 안전 한도이며 ZEP 공식 한도가 아닙니다. 기록이 한도에 도달하면 추가 쓰기 전 중지합니다. 대규모 운영 전 실제 ZEP 용량을 확인하고 필요시 이 안전 설정을 조정하세요. 큐 최대 100건과 15초 응답 제한도 처리 보호용이며 경품 재고와는 별개입니다.
