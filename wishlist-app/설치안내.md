# 부스 위시리스트 v1.4

독립적인 ZEP Normal app입니다. 기존 코인·스탬프 앱을 덮어쓰지 말고 별도 앱으로 등록하세요.

## 설치

1. `zep-booth-wishlist-v1.4.zepapp.zip`을 압축 해제하지 않고 ZEP 나의 앱에 업로드합니다. 대상 맵에서 자동 실행하도록 적용하세요.
2. 각 부스의 하트 오브젝트 이름에 부스 이름을 입력합니다.
3. 하트의 상호작용을 **ZEP Script 상호작용**으로 설정합니다.
4. **번호**에 고유한 부스 번호(숫자 1~12자리)를 넣습니다. `001`과 `1`은 별개 번호입니다.
5. **값**에 `wishlist:부스 이름`을 입력합니다. 예: 번호 `101`, 오브젝트 이름 `디자인 부스`, 값 `wishlist:디자인 부스`.
6. 실행 방법은 **F키를 눌러 실행**, 실행 범위는 1로 설정하고 저장합니다.

공식 문서에서 확실히 제공하는 이벤트 필드는 번호 `obj.text`와 값 `obj.param1`입니다. 오브젝트 이름 `obj.name`은 전달되는 경우 우선 사용하지만, 편집기 이름의 전달을 보장하지 않으므로 **값에도 부스 이름을 입력해 주세요.** 이름을 바꾸면 값의 이름도 함께 바꾸세요. `wishlist` 접두어는 다른 앱의 오브젝트와 구분하기 위해 필수입니다. 이름 전달이 확인된 환경에서는 값 `wishlist`만 사용할 수 있습니다.

## 사용

- 하트에서 F키: 내 위시리스트에 등록합니다. 같은 번호는 중복되지 않으며 이름·이동 위치가 갱신됩니다.
- 목록의 부스 이름/번호: 해당 부스로 이동합니다.
- 휴지통 아이콘: 해당 항목만 삭제합니다. 하트를 다시 누르면 재등록됩니다.
- 정렬 아이콘 옆 선택: 최근 추가순, 부스 번호순, 이름순. 정렬 선택도 저장됩니다.
- 위쪽 **접기** 버튼: 목록을 숨기고 좌측 채팅창 우측 하단 부근에 최대 48×48px 하트 아이콘만 남깁니다. 아이콘을 누르면 펼쳐집니다. 채팅 `!wishlist`: 접힌 상태에서도 목록을 펼쳐 다시 엽니다.
- 개인별 최대 200개. 다른 사용자의 목록과 독립적입니다.

기본 도착 위치는 하트에서 F키를 누른 순간 플레이어가 서 있던 타일입니다. 하트 타일 자체가 막혀 있을 수 있어 플레이어 위치를 사용합니다. 원하는 부스 입구로 고정하려면 `main.js`의 `CONFIG.destinations`에 `'101': {x:12, y:8}`처럼 등록하고 다시 빌드하세요. 이동 타일은 관리자가 직접 통행 가능 여부를 확인해야 합니다. 하트/부스를 옮기면 재등록하거나 destinations를 수정하세요. 오래된 기록을 일괄 분리하려면 mapKey를 변경할 수 있지만 기존 목록은 새 키에서 보이지 않습니다.

**한 맵용 앱입니다.** 다른 맵에 적용할 때는 `CONFIG.mapKey`를 고유하게 바꾸고 별도 빌드하세요. 맵 간 이동은 구현하지 않습니다. 이 앱을 여러 맵에서 같은 mapKey로 사용하면 좌표가 섞일 수 있습니다.

## UI와 검증 범위

밝은 배경, 둥근 모서리, 보라색 강조와 간단한 아이콘으로 ZEP 기본 UI에 맞춘 HTML 위젯입니다. ZEP 내장 위시리스트 컴포넌트는 아닙니다. 기본 배치는 우측이며 `CONFIG.ui`에서 화면 대비 위·오른쪽·아래·왼쪽 여백을 조정합니다. 모바일에서는 여백을 조정해 주세요.

저장은 player.storage JSON의 `zepWishlist[mapKey]`에 기록하고 player.save()를 호출합니다. 기존 JSON의 다른 필드를 보존하고, 손상 기록은 덮어쓰지 않습니다. 다른 앱과 동시 저장 및 게스트 영구 저장은 실제 ZEP에서 검증해야 합니다. save() 반환만으로 영구 저장 완료까지 확인할 수는 없습니다.

모의 런타임 테스트 10개와 JS 구문 검사, ZIP 내용 검사를 통과했습니다. 실제 ZEP 실행 및 브라우저 시각 검증은 수행하지 않았습니다. 업로드 후 F키 등록, 이름 표시, 다른 계정 목록 분리, 재접속 유지, 삭제, 정렬, 이동 위치와 PC·모바일 배치를 확인하세요.

## 개발

`node wishlist-app/test.cjs`로 테스트합니다. 빌드: `python3 wishlist-app/build.py`.
ZIP 최상위에는 main.js, wishlist.html, wishlist-mini.html이 포함됩니다.

공식 API 근거:
- https://docs.zep.us/zep-script/zep-script-guide/appendix/object-interaction-with-zep-script
- https://docs.zep.us/zep-script/zep-script-api/scriptplayer/methods

## v1.2 접기 오류 수정

위젯 destroy()의 반환값을 실패로 오판하던 검사를 제거했습니다. 제거 호출에서 예외가 발생하면 기존 위젯 안에서 목록을 접거나 펼칩니다. 이 예외 경로에서는 위젯 외곽 영역은 원래 크기로 남아 지도 클릭을 가릴 수 있지만, 접기·펼치기와 목록 기능은 계속 사용할 수 있습니다. 정상 제거 경로에서는 위젯 영역도 축소됩니다.

## v1.3 최소화 아이콘

접으면 `showWidget`으로 오른쪽 중앙(`middleright`)에 64×64px 위젯을 표시하고, 그 안에 48×48px 하트와 저장 개수 배지를 보여줍니다. 긴 제목·펼치기 문구는 제거했습니다. 좌측 화상 화면과 하단 조작부를 피하는 기본 배치이며 모든 ZEP UI 상태에서 겹침을 보장하지는 않습니다. 오른쪽 패널을 사용하는 맵에서는 `CONFIG.minimized.align`을 `middleleft`, `topright` 등으로 변경할 수 있습니다. 펼친 목록의 위치는 기존대로 유지합니다. 제거 API 예외가 발생하면 이전 버전과 같이 기존 위젯 내부에서 작은 아이콘을 표시하므로 그 경우 위치 이동·위젯 영역 축소는 적용되지 않습니다.

## v1.4 최소화 위치 이동

최소화 아이콘을 좌측 채팅창 우측 하단 부근으로 옮겼습니다. CONFIG.minimized의 여백은 위 76%, 오른쪽 64%, 아래 12%, 왼쪽 28%입니다. ZEP 채팅창 경계를 자동 감지하는 방식이 아니므로 화면 크기·채팅창 너비에 따라 위치 차이가 있습니다. 필요하면 left(가로 위치)와 top(세로 위치)을 조정하고 반대 여백도 함께 조정하세요. 펼친 위시리스트 위치와 기존 저장 목록은 그대로입니다.
