# 부스·장소 위시리스트 v2.2 — 모든 맵에서 목록 보기

## 모든 맵에서 보이게 하는 방법

목록은 현재 맵에 상관없이 같은 스페이스의 저장 항목 전체를 표시합니다. **앱이 실행되지 않는 맵에는 코드만으로 창을 띄울 수 없습니다.** ZEP 관리 화면에서 아래 중 한 방식으로 적용해야 합니다.

### 기존 기록을 유지하는 권장 방법: 현재 노멀 앱을 모든 맵에 적용

1. 기존 위시리스트 앱을 v2.2 ZIP으로 업데이트합니다. 새 앱을 만들지 마세요.
2. 맵 편집기의 맵 관리자에서 **각 맵의 설정(⚙️ → 수정/편집)**을 엽니다.
3. Application/앱 항목에서 **동일한 위시리스트 앱**을 선택해 저장합니다. 화면 버전에 따라 Settings → Map Settings → Add Normal App 경로일 수 있습니다.
4. 부스가 없는 로비·휴게실·통로 맵까지 모두 적용하세요. 새 맵을 만들 때도 앱을 적용해야 합니다.
5. 각 맵에 재접속하면 전체 목록이 자동 표시됩니다. 하트를 다시 등록할 필요는 없습니다(v2.0에서 등록한 항목 기준).

### 스페이스 전체의 사이드바에서 접근하는 방법

공식 가이드에 따르면 Sidebar App은 스페이스에 설치하면 입장자 전체의 PC 사이드바에 표시됩니다. v2.2 ZIP은 이 유형도 지원하며 사이드바 아이콘을 누르면 위시리스트를 펼칩니다.

ZEP 나의 앱에서 앱 유형을 Sidebar App으로 설정하고, 플레이 화면의 **앱 → 앱 관리**에서 스페이스에 추가하세요. ZEP UI에서 기존 앱의 유형 변경이 가능한지 먼저 확인하세요. **별도 사이드바 앱을 새로 등록하면 앱 ID가 달라져 기존 앱의 저장 기록이 자동 이전된다고 보장할 수 없습니다.** 기록을 유지하려면 위의 노멀 앱 적용 방식이 안전합니다. 동일 기능의 노멀 앱과 사이드바 앱을 중복 실행하지 마세요. 사이드바의 모바일 노출은 실제 기기에서 확인해야 합니다.

v2.2은 사이드바 클릭과 앱 실행 시 이미 접속 중인 플레이어의 창 초기화를 추가했습니다. ZEP 스페이스의 설치 설정 자체를 ZIP이 자동 변경하지는 않습니다.

공식 설치 안내:
- https://docs.zep.us/zep-script/zep-script-guide/zep-script-development-guide
- https://docs.zep.us/zep-script/zep-script-guide/zep-script-development-guide/zep-script-deployment-guide

## 설치와 적용 범위

1. `dist/zep-booth-wishlist-v2.2.zepapp.zip`을 압축 해제하지 않고 **기존 위시리스트 앱 업데이트**에 사용하세요. 별도의 앱으로 새로 등록하면 기존 앱의 개인 저장 기록을 공유하지 못할 수 있습니다.
2. **같은 스페이스의 출발·도착 맵 모두에서 동일한 앱을 자동 실행**하도록 적용하세요. 모든 맵에 v2.2을 적용하고 이전 앱/버전의 중복 실행을 정리하세요.
3. 각 맵의 하트 오브젝트는 아래 예시로 연결합니다. 맵별로 mapKey를 바꿀 필요가 없습니다. 맵 ID는 `App.mapHashID`에서 자동으로 읽습니다.

이 버전은 **같은 스페이스 안의 맵 간 이동**을 지원합니다. 다른 스페이스 사이의 저장 공유·정확한 좌표 이동은 지원하지 않습니다. 도착 맵에 앱이 없으면 맵의 기본 입장 위치까지만 이동하고 저장된 좌표로 이동하는 후속 처리는 실행되지 않습니다. 비공개·입장 제한 맵의 접근 권한을 우회하지 않습니다.

## 일반 부스 또는 현재 장소 저장

| 오브젝트 설정 | 입력 예시 |
|---|---|
| 이름 | 디자인 부스 |
| 상호작용 | ZEP Script 상호작용 |
| 번호 | `101` |
| 값 | `wishlist:디자인 부스` |
| 실행 방법 | F키를 눌러 실행 |
| 실행 범위 | 1 |

하트에서 F키를 누르면 부스 이름·번호와 **현재 맵 ID, 당시 플레이어가 서 있던 타일**을 함께 저장합니다. 부스뿐 아니라 쉼터·안내 데스크 등 원하는 장소에 같은 방식으로 하트를 배치할 수 있습니다. 같은 맵 안에서는 번호가 고유해야 합니다. 다른 맵의 같은 번호는 서로 다른 항목으로 저장됩니다.

목록을 클릭하면:
- 같은 맵: 저장된 위치로 바로 이동합니다.
- 다른 맵: 이동 요청을 저장하고 `spawnAtMap`으로 맵을 바꿉니다. 도착 맵의 앱이 입장 이벤트에서 요청을 읽고 `spawnAt` 또는 `spawnAtLocation`으로 목적지에 배치합니다.

등록 당시 위치는 통행 가능한 장소여야 합니다. 하트를 옮겼다면 다시 상호작용해 위치를 갱신하세요. 오브젝트 이름이 SDK 이벤트로 전달되지 않는 경우에도 동작하도록 값에도 부스 이름을 넣어주세요.

## 다른 맵의 특정 위치를 지정하는 하트

현재 맵에서 다른 맵의 장소를 저장시키고 싶다면 **값**에 다음 JSON 형식을 넣을 수 있습니다. 번호는 평소처럼 별도 입력합니다.

```text
wishlist:{"name":"2전시장 안내 데스크","mapId":"실제목적지맵ID","x":12,"y":8}
```

- `mapId`는 목적지 맵의 실제 해시 ID입니다. 맵 이름이나 URL 전체를 넣지 마세요.
- `x`, `y`는 이미지 픽셀이 아닌 ZEP **타일 좌표**입니다.
- 목적지에서 채팅 `!wishlist-map`을 입력하면 스페이스 ID, 맵 ID, 현재 타일 좌표를 개인 메시지로 확인할 수 있습니다.
- JSON에는 `name`과 `mapId`, 그리고 `x`·`y` 또는 아래 `location`이 필요합니다. 따옴표·중괄호도 그대로 입력하세요.

ZEP Script용 지정 영역 이름으로 목적지를 관리할 수도 있습니다.

```text
wishlist:{"name":"상담실","mapId":"실제목적지맵ID","location":"meeting-room"}
```

목적지 맵에 `meeting-room`이라는 **ZEP Script 지정 영역**을 먼저 설치하세요. 같은 이름을 여러 곳에 지정하면 ZEP에서 무작위 위치로 이동할 수 있으므로 목적지 영역 이름을 고유하게 지정하세요. `location`과 좌표가 함께 있으면 지정 영역을 사용합니다.

코드로 관리하는 경우 `CONFIG.destinations`에 현재 맵의 번호별 `{mapId:'...', x:12, y:8}` 또는 `{mapId:'...', location:'...'}`를 설정하고 다시 빌드할 수도 있습니다. JSON 값이 있으면 JSON 목적지를 우선합니다.

## 기존 v1.x 기록

v1.x에는 맵 정보가 없으므로 다른 맵에서 같은 좌표로 잘못 이동시키지 않습니다. 기본값에서는 기존 목록을 `재등록 필요`로 표시하고 이동을 차단합니다. **원래 부스에서 하트를 다시 누른 뒤 예전 항목을 삭제**하세요. 새로 등록한 항목에는 맵 정보가 있어 이후에는 어느 맵에서든 이동할 수 있습니다.

기존 기록의 출처가 전부 한 맵임을 확실히 아는 관리자는 `CONFIG.legacyMapId`에 **기존 기록의 원래 맵 ID**를 입력해 빌드할 수 있습니다. 이전에 mapKey를 변경했다면 `CONFIG.legacyMapKey`도 기존 값으로 맞추세요. 설정은 공유 기록 v2가 처음 저장되기 전에 적용해야 합니다. 이미 만들어진 공유 기록을 설정 변경만으로 다시 변환하지는 않습니다.

새 저장 필드는 `player.storage` JSON의 `zepWishlistShared`(version=2)이며, 기존 `zepWishlist`와 다른 기능의 JSON 필드는 보존합니다. 기존 단일 맵 기록 여러 개를 자동으로 합치지는 않습니다. 저장 데이터가 손상된 경우 덮어쓰지 않습니다. 같은 앱·스페이스에서 사용해야 하며, 게스트 지속성과 다른 앱의 동시 저장은 실제 환경에서 확인하세요.

## UI·명령어

- 다른 맵의 항목은 이름 옆에 ↗를 표시합니다.
- 휴지통은 해당 항목만 삭제합니다. 같은 번호라도 맵이 다르면 다른 항목입니다.
- 최근 추가순·번호순·이름순과 정렬 선택 저장을 지원합니다.
- 접으면 v1.6과 동일하게 초록 박스 기준 위치에 작은 하트 아이콘을 표시합니다. 화면 크기에 따라 위치는 달라질 수 있습니다.
- `!wishlist`: 목록 펼치기.
- `!wishlist-map`: 현재 맵 ID·현재 타일 확인.
- `!wishlist-cancel`: 진행 중인 맵 이동 요청 취소. 입장 권한 문제 등으로 맵 이동이 실행되지 않았다면 취소 후 다시 선택하세요.

맵 이동 요청은 2분 후 만료되며, 만료 후 입장하면 자동 좌표 이동을 하지 않습니다. 도착 요청은 한 번만 소비하고, 목적지 좌표는 도착 맵의 범위로 검사합니다. 맵 이동 API 호출 성공을 실제 입장 완료로 간주하지 않습니다. 도착 처리는 대상 맵의 앱 실행과 player.storage 전달에 의존합니다. 저장 API 반환만으로 서버 영구 저장·맵 간 동기화 완료까지 확인할 수는 없습니다.

## 빌드 및 검증

```sh
python3 wishlist-app/build.py
```

빌드 결과 ZIP 최상위에는 main.js, wishlist.html, wishlist-mini.html이 포함됩니다. 모의 ZEP 환경에서 같은 맵 이동, 맵 간 왕복, 지정 영역, 같은 번호의 구분, 도착 좌표 범위, 실패·취소·만료, 이전 데이터 보호, 접기·펼치기 등 30개 테스트와 JS 구문·ZIP 검사를 통과했습니다.

**실제 ZEP에서의 맵 전환 및 저장 전달은 아직 검증하지 않았습니다.** 적용 후 A맵에서 등록 → B맵에서 목록 확인 → A맵 항목 선택 → A맵의 등록 위치 도착 → 반대 방향 이동 → 재접속·다른 계정 테스트를 진행하세요. 두 맵 모두 동일 앱 v2.2이 실행되어야 합니다.

공식 API 근거:
- https://docs.zep.us/zep-script/zep-script-api/scriptapp/field (App.spaceHashID, App.mapHashID)
- https://docs.zep.us/zep-script/zep-script-api/scriptplayer/methods (spawnAtMap, spawnAt, spawnAtLocation, save)
- https://docs.zep.us/zep-script/zep-script-guide/appendix/object-interaction-with-zep-script

## v2.2 맵 이름 표시

목록은 **부스번호 / 기업명 / 맵 이름**을 표시합니다. 기업명 아래에 `맵 · 제1전시장`처럼 작은 글씨로 표시하며, 다른 맵의 항목에는 기존처럼 ↗가 붙습니다.

- 일반 하트: 등록 시 공식 API `Map.name`으로 현재 맵 이름을 읽어 함께 저장합니다. 기존 `wishlist:기업명` 설정 그대로 사용합니다.
- v2.0/v2.1의 기존 항목: 해당 맵을 방문하면 맵 이름을 자동으로 보완·저장합니다. 아직 이름을 알 수 없는 다른 맵의 항목에는 `맵 이름 확인 필요`가 표시됩니다. 이 표시는 이동을 막지 않습니다.
- 맵 이름 변경: 해당 맵을 다시 방문하면 그 맵의 항목 이름 정보를 갱신합니다.
- 다른 맵 목적지를 직접 지정한 JSON: 목적지 맵의 이름도 `mapName`으로 지정할 수 있습니다. 생략하면 해당 맵을 방문한 뒤 이름이 보완됩니다. 출발 맵의 이름을 다른 맵 목적지의 이름으로 저장하지 않습니다.

```text
wishlist:{"name":"안내 데스크","mapId":"실제목적지맵ID","mapName":"제2전시장","x":12,"y":8}
```

관리자는 `CONFIG.mapNames`에 `'맵ID': '표시할 맵 이름'` 형식으로 이름을 미리 지정할 수 있습니다. 이 설정은 저장된 이름 및 자동 조회 이름보다 우선합니다. 맵 이름을 조회할 수 없는 SDK 환경에서도 등록·이동 기능은 유지됩니다. 긴 기업명·맵 이름은 줄바꿈하며, HTML로 해석하지 않고 텍스트로 표시합니다.

공식 API 근거: https://docs-kr.zep.us/zep-script-api/zepscriptapi/scriptmap/field (`Map.name`)
