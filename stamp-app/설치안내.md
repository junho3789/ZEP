# 오브젝트 스탬프 앱 · v1.1

구역·좌표 판정 없이 지정 오브젝트 4개의 상호작용으로 수집합니다. 별도 앱으로 제작했으며 기존 코인/투표 앱 코드는 수정하지 않았습니다.

## 설정 후 업로드
1. main.js 상단 CONFIG의 objects[].url에 프로그램 HTTPS 링크 4개, formUrl에 구글폼 HTTPS 링크를 입력하세요. 현재 빈 링크이며 링크를 설정하지 않은 오브젝트는 지급하지 않습니다.
2. main.js와 stamp-ui.html을 ZIP 최상위에 넣어 압축합니다. 제공 ZIP을 사용하려면 먼저 링크를 수정한 파일로 다시 압축하세요.
3. ZEP 나의 앱에서 Normal app으로 업로드하고 대상 맵에 적용합니다. 기존 코인 앱의 업데이트 파일로 올리지 말고 별도 앱으로 추가하세요.
4. 맵 편집기에서 아래 5개 오브젝트에 ZEP Script 상호작용을 설정합니다. 실행 방법은 반드시 **F키를 눌러 실행**으로 설정합니다. 웹링크 열기 기본 기능을 중복 설정하지 마세요. 링크는 앱에서 엽니다.

| 설치 오브젝트 | 번호 | 값 |
|---|---|---|
| 프로그램 1 | 201 | stamp:1 |
| 프로그램 2 | 202 | stamp:2 |
| 프로그램 3 | 203 | stamp:3 |
| 프로그램 4 | 204 | stamp:4 |
| 안내데스크 | 205 | stamp:desk |

이 프로젝트에 있던 ZEP 코드와 가이드 인용에 따라 type 21 오브젝트의 text(번호), param1(값)을 사용합니다. onObjectTouched 이벤트는 맵 편집기의 실행 설정을 따릅니다. 이름 때문에 직접 접촉 지급으로 오해하지 않도록 F 실행 설정을 확인하세요. 현재 맵/계정에 접속하지 않았으므로 실제 설치와 링크 설정은 미적용입니다.

## 변경 항목
- objects: 오브젝트 추가/삭제, name, number, value, url, enabled 수정 가능. 번호는 서로 달라야 합니다.
- requiredStamps: 기본 4. 활성 오브젝트 수 이하의 양의 정수.
- formUrl: 구글폼 링크.
- eventId: 새 행사 시 변경. 같은 행사의 기존 기록을 유지하려면 변경하지 마세요.
- objects[].id: 기록의 기준값입니다. 이름이나 링크만 바꿀 때 id는 유지하세요. 비활성화/삭제된 항목은 응모 개수에서 제외합니다.
- ui: 화면 대비 % 여백(top, right, bottom, left). 기본 왼쪽 7%, 위 8%로 좌상단 앱 영역 오른쪽을 의도했습니다. 맵의 기본 UI에 맞춰 조정하세요. collapsedBottom은 접힌 상태의 아래쪽 여백입니다. 접기/펼치기는 위젯을 작은 크기로 다시 생성해 아래 맵을 덮는 영역을 줄입니다. 모바일에서는 화면 비율에 맞춘 별도 여백 조정이 필요할 수 있습니다.

## UI
흰 카드, 연보라색 강조, 둥근 스탬프 슬롯과 체크 표시로 ZEP 분위기를 참고했습니다. 공식 기본 스탬프 UI를 직접 확인하거나 복제한 것은 아닙니다. 펼침: 현황/진행률/오브젝트별 수집 여부/안내. 접힘: 제목과 수집 개수. UI에서는 지급이나 응모를 요청할 수 없고 실제 오브젝트 이용만으로 지급합니다. !stamps로 현황 확인 및 UI 재생성이 가능합니다.

## 저장과 링크의 의미
- 링크 열기 호출이 예외 없이 반환된 시점에 지급합니다. 실제 로딩·새 탭 표시·프로그램 완료는 검증하지 않습니다. 브라우저가 조용히 차단하는 경우까지 감지하지 못합니다.
- 같은 이용자/이벤트/오브젝트는 한 번만 지급. 재이용 시 링크만 다시 엽니다.
- player.storage JSON의 zepStampEvents에 저장하고 player.save() 호출. 다른 JSON 필드는 보존하며 손상된 기록은 덮어쓰지 않습니다.
- save 호출 성공이 서버 영구 저장 완료를 보장하지 않습니다. 동일 계정 재접속 검증이 필요합니다. 게스트/계정 변경/다른 스페이스/동시 세션의 지속성은 실제 ZEP에서 확인하세요.
- 4개 획득 시 안내데스크가 구글폼을 엽니다. 구글폼 제출 완료는 추적하지 않으며 데스크 재이용이 가능합니다. 링크 공유를 통한 직접 응모는 차단하지 않습니다. 개인정보 동의와 중복 제출 정책은 구글폼에서 설정하세요.

## 검증
Node VM에서 지급, 중복 방지, 데스크 조건, 설정 변경, 재접속 복원, 접기 메시지/위젯 크기 변경, 다른 저장 필드 보존, 빈 링크, 링크 호출 오류, 저장 오류와 손상 기록 보호를 검증했습니다. 실제 ZEP API·렌더링·영구 저장은 미검증입니다. 온라인 공식 문서 조회가 실패하여 작업공간의 기존 구현을 참고했습니다. 배포 전에 오브젝트 4개 F 실행, 재방문, 재접속, 데스크 3/4와 4/4, 링크 새 창, PC/모바일 UI 위치 및 접힌 영역을 확인하세요.


## 코드 구성 및 빌드
- `main.js`: CONFIG → 공통 함수 → 저장 처리 → UI → 링크/상호작용 → ZEP 이벤트 연결 순서입니다.
- `stamp-ui.html`: 스타일, 화면 구조, 렌더링 스크립트를 구분했습니다. renderState는 전체 현황, renderStamp는 개별 스탬프를 그립니다.
- 설정 키와 저장 형식은 v1과 같습니다. 기존 획득 기록을 유지하려면 eventId와 오브젝트 id를 유지하세요.
- 링크를 입력한 뒤 이 폴더에서 `python3 build.py`를 실행하면 검사 후 `zep-object-stamps-v1.1.zepapp.zip`을 생성합니다. 같은 이름의 v1.1 ZIP은 현재 소스로 갱신하며 이전 v1 ZIP은 보존합니다.
- 이번 변경은 구조 정리이며 디자인과 기본 배치, 응모 조건은 동일합니다. 실제 ZEP 설치 검증은 별도로 필요합니다.
