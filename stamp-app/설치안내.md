# 오브젝트 스탬프 앱 · v1.3-admin-reset

## 이번 수정
- 프로그램과 구글폼 모두 `player.openWebLink(url, true)`로 ZEP 기본 팝업에 표시합니다. 별도 팝업 위젯이나 화면 전체 투명 덮개는 만들지 않습니다.
- 같은 링크의 연속 F 입력을 기본 1.2초 동안 제한합니다. 팝업을 닫은 뒤 시간이 지나면 다시 열 수 있습니다.
- 수집 UI 클릭·포인터 해제·마우스 이탈·방향키 입력 시 UI 포커스를 해제하고 부모 화면에 포커스를 요청합니다. 프로그램/폼 내부 입력에는 관여하지 않습니다.
- 이전 UI 제거 실패 시 추가 UI를 겹쳐 만들지 않습니다. UI 제거 후 이전 위젯의 지연 메시지를 무시하며, 앱 종료 시 UI도 정리합니다.
- 캐릭터 moveSpeed, 위치, 이동 제한 상태는 변경하지 않습니다. 움직임 먹통의 정확한 원인을 실제 맵에서 재현한 것은 아닙니다. 포커스/중복 실행을 보완한 버전입니다.

## 다운로드와 업데이트
ZIP: https://github.com/junho3789/ZEP/raw/refs/heads/main/dist/zep-object-stamps-v1.3.zepapp.zip

1. 기존 앱을 **삭제하지 말고 업데이트**하세요. 동일 앱으로 업데이트하고 eventId와 objects[].id를 유지해야 기존 수집 기록을 이어갈 수 있습니다.
2. 공개 ZIP의 링크는 빈칸입니다. main.js 상단 CONFIG에 운영 중인 프로그램 링크 4개와 구글폼 링크를 입력하세요. 기존에 수정한 링크·오브젝트 번호·값·UI 위치도 유지하세요.
3. `python3 build.py`를 실행해 ZIP을 다시 만듭니다. Python을 사용하지 않는 경우 main.js와 stamp-ui.html 두 파일이 ZIP 최상위에 오도록 압축해도 됩니다.
4. ZEP 나의 앱에서 기존 스탬프 앱에 새 ZIP을 업로드하고 대상 맵에서 Normal app으로 적용합니다. 동일 역할의 이전 앱을 중복 실행하지 마세요.
5. 맵을 나갔다 다시 들어와 `!stamp-version`을 입력하세요. `1.2-popup`이 표시돼야 새 코드가 실행 중입니다.

## 오브젝트 연결
ZEP Script 상호작용 → 실행 방법 **F키를 눌러 실행** → 실행 범위 1로 시작합니다. 기본 웹링크 열기 동작을 별도로 중복 설정하지 마세요.

| 설치 오브젝트 | 번호 | 값 |
|---|---|---|
| 프로그램 1 | 201 | stamp:1 |
| 프로그램 2 | 202 | stamp:2 |
| 프로그램 3 | 203 | stamp:3 |
| 프로그램 4 | 204 | stamp:4 |
| 안내데스크 | 205 | stamp:desk |

구역/좌표 판정을 사용하지 않습니다. type 21 오브젝트의 text(번호), param1(값)을 사용합니다. onObjectTouched는 편집기에서 정한 실행 방법을 따릅니다.

## 변경 가능한 설정
- `objects`: 추가/삭제, name, number, value, url, enabled. 번호는 서로 달라야 합니다.
- `requiredStamps`: 기본 4. 활성 오브젝트 수 이하의 양의 정수.
- `formUrl`: 구글폼 HTTPS 링크.
- `popupCooldownMs`: 같은 링크의 연속 호출 제한 시간. 기본 1200ms.
- `eventId`: 새 행사 시 변경. 기존 행사 기록을 유지하려면 그대로 둡니다.
- `objects[].id`: 수집 기록의 기준값. 이름/링크만 바꿀 때는 유지합니다. 비활성화/삭제된 항목은 응모 개수에서 제외합니다.
- `ui`: 위·오른쪽·아래·왼쪽 화면 대비 % 여백. 기본 좌측 7%, 위 8%. 모바일/화면 비율에 따라 실제 위치를 확인하세요. collapsedBottom은 접힌 상태 아래쪽 여백입니다.

## UI와 진단 명령
흰 카드, 보라색 강조, 원형 스탬프 슬롯의 기존 디자인을 유지했습니다. 펼치면 개별 스탬프·진행률·안내, 접으면 제목과 개수를 표시합니다.

- `!stamp-version`: 실행 버전 확인.
- `!stamp-ui-hide`: 수집 UI 제거. 수집 기록은 보존합니다.
- `!stamps`: 수집 현황 확인 및 UI 다시 표시.

팝업을 닫은 후 이동이 안 되면 먼저 맵 빈 바닥을 클릭하세요. 이어서 `!stamp-ui-hide`를 입력하고 채팅 입력을 끝낸 뒤 맵을 클릭해 이동 여부를 확인하세요. UI를 숨겼을 때만 정상이라면 HUD 포커스/범위를 추가 조사할 수 있습니다. ZEP 기본 팝업은 ZEP의 닫기 버튼으로 닫아야 하며, 위 명령은 기본 팝업을 강제로 닫는 기능이 아닙니다.

## 저장과 링크 기준
- 링크 열기 호출이 예외 없이 반환된 시점에 지급합니다. 실제 페이지 로딩·프로그램 완료는 검증하지 않습니다.
- 동일 이용자/이벤트/오브젝트는 한 번만 지급. 재이용 시 팝업만 다시 엽니다.
- player.storage JSON의 zepStampEvents에 저장하고 player.save()를 호출합니다. 다른 필드는 보존하고 손상된 기록은 덮어쓰지 않습니다.
- save 반환이 영구 저장 완료를 보장하지는 않습니다. 동일 계정 재접속으로 확인하세요. 게스트/계정 변경/다른 스페이스/동시 접속의 지속성도 실제 ZEP에서 확인 대상입니다.
- 구글폼 제출 완료는 추적하지 않습니다. 링크 공유를 통한 직접 응모도 차단하지 않습니다. 개인정보 동의와 중복 제출 정책은 구글폼에서 설정하세요.
- 프로그램/폼 제공 서비스가 임베드를 차단하면 팝업 안에 표시되지 않을 수 있습니다. 실제 운영 링크로 확인하세요.

## 검증 범위

## 관리자 채팅 초기화 (v1.3)
권한은 서버의 player.role로 확인합니다. 관리자(3000)·맵 소유자(3001)만 실행할 수 있습니다. 스태프(2000), 에디터(1000), 일반 이용자는 사용할 수 없습니다.

| 명령 | 기능 |
|---|---|
| `!stamp-reset me` | 관리자 본인의 초기화 요청 |
| `!stamp-players` | 현재 맵 접속자의 이름과 ID 확인 |
| `!stamp-reset id 이용자ID` | 해당 ID의 현재 접속자 초기화 요청 |
| `!stamp-reset all` | 요청 시점 현재 맵 접속자 전체의 초기화 요청 |
| `!stamp-reset confirm` | 30초 안에 요청을 확인해 초기화 실행 |
| `!stamp-reset cancel` | 요청 취소 |

예: `!stamp-reset all` 입력 → 대상 수 확인 → `!stamp-reset confirm` 입력.
현재 CONFIG.eventId의 스탬프만 비웁니다. 다른 이벤트, 코인 등 저장 데이터는 유지됩니다. 해당 이용자 UI는 즉시 0개로 갱신되고 다시 수집할 수 있습니다. 초기화 후 재접속 시에도 0개인지 확인하세요. player.save 호출만으로 영구 저장 완료를 보장하지는 않습니다.

전체 초기화는 이 맵/앱 인스턴스에서 접속 중인 이용자만 대상으로 합니다. 미접속자·다른 맵·다른 서버 이용자의 저장 기록을 일괄 삭제하지 않습니다. 요청 이후 입장한 이용자는 포함하지 않고, 확인 전에 퇴장한 이용자는 제외합니다. 닉네임 대신 정확한 ID를 사용합니다. 확인 명령은 일회성이며, 확인 시 관리자 권한도 다시 검사합니다.

오류/퇴장자는 건너뛰고 결과 인원수를 관리자에게 알립니다. 저장 예외 시 이전 데이터를 복원하며, 손상된 기록은 자동 덮어쓰지 않습니다. 권한 차단·확인 만료/취소·대상 고정·개별/전체 초기화·다른 이벤트 보존·저장 실패·재수집을 추가 테스트했습니다.

권한 근거: https://docs-kr.zep.us/zep-script-api/zepscriptapi/scriptplayer/field
