## 이번 수정
- 스탬프 부족 상태로 응모 데스크에서 상호작용하면 채팅 대신 전용 **응모 안내 팝업**을 표시합니다. 키비주얼의 라임·블루·블랙을 적용했으며 현재 수집 수/필요 수/부족 수를 보여줍니다.
- 스탬프 조건을 충족하면 기존 구글폼 링크를 엽니다.

- 카드의 키비주얼 색상, 홀로그램과 회전 광원, 카드 바로 아래 닫기 버튼은 유지합니다. 카드를 닫은 뒤 별도의 발견 알림은 표시하지 않습니다.
- 수집 창 안의 4번 스탬프 그림과 미니 아이콘은 이전 원본 캐릭터를 유지합니다. 이번 새 그림은 스페셜 카드에만 적용합니다.

## 업데이트: 운영 설정 보존
**이번에는 main.js와 새 stamp-entry.html이 필요하므로 HTML만 교체하면 전체 수정이 적용되지 않습니다.**

1. 기존 main.js를 백업합니다.
2. 기존 CONFIG의 프로그램 1~3 URL, formUrl, eventId, requiredStamps, 오브젝트 id/number/value/name/enabled 및 UI 위치를 새 main.js에 옮깁니다.
3. 4번은 링크가 필요하지 않습니다. foundStampId는 카드 오브젝트의 id이며 기본 s4입니다. 기존 4번 id가 다르면 같은 값으로 설정하세요.
4. ZIP 최상위에 main.js, stamp-ui.html, stamp-mini.html, stamp-special.html, stamp-entry.html 다섯 파일을 넣습니다. python3 build.py로 검사 후 압축할 수도 있습니다.
5. 기존 앱을 삭제하지 않고 ZIP으로 업데이트하고 재접속합니다. !stamp-version에서 1.8-newton-study를 확인하세요.

배포용 기본값의 프로그램 1~3 URL과 formUrl은 빈칸입니다. 운영 링크를 옮기지 않고 main.js를 덮어쓰면 해당 링크가 열리지 않습니다. eventId와 오브젝트 id를 유지하면 기존 기록을 이어갑니다. 그림은 HTML 내부에 포함돼 별도 이미지 경로 해석이나 외부 요청이 필요하지 않습니다.

| 오브젝트 | 번호 | 값 |
|---|---|---|
| 프로그램 1 | 201 | stamp:1 |
| 프로그램 2 | 202 | stamp:2 |

1~3번은 링크 열기 호출 시 수집하며 프로그램 완료 여부는 확인하지 않습니다. 4번은 카드 열기와 저장이 성공하면 수집합니다. 재방문해도 스탬프는 중복 지급하지 않습니다. 카드/안내 팝업은 같은 종류의 창을 겹쳐 만들지 않습니다. 저장 실패와 손상 기록은 안내하며 다른 JSON 필드는 보존합니다.

## UI와 채팅 명령
- 수집 창은 접으면 좌측 상단 뉴턴 아이콘만 표시하며 클릭하면 다시 펼쳐집니다.
- 카드와 닫기 버튼은 하나의 반응형 묶음이며 하단 기본 UI 영역과 safe-area를 예약합니다. 키보드 Escape로도 닫을 수 있습니다.
- 응모 안내는 현재 수집 수를 서버에서 읽어 표시합니다. 닫기 버튼으로 맵에 돌아갑니다. 좁고 낮은 화면에서는 안내 내용 부분만 스크롤되고 닫기 버튼은 유지됩니다.
- !stamps: 현황 확인 및 수집 창 펼치기.
- !stamp-ui-hide: 수집 창/아이콘 숨기기.
- !stamp-version: 실행 버전 확인.
- !stamp-players: 접속자 이름/ID 조회. 관리자 또는 맵 소유자만 가능.
- !stamp-reset me / !stamp-reset id 이용자ID / !stamp-reset all: 현재 이벤트 스탬프 초기화 요청.
- !stamp-reset confirm: 30초 안에 확인해 초기화 실행.
- !stamp-reset cancel: 초기화 취소.

관리자 role=3000, 맵 소유자 role=3001만 초기화할 수 있습니다. 전체 초기화는 요청 시 현재 맵 접속자만 대상으로 하며 미접속자/다른 서버는 제외합니다. 관리자 초기화와 퇴장/앱 종료 시 열려 있는 관련 팝업도 정리합니다. 실제 영구 저장은 동일 계정 재접속으로 확인하세요.

## 검증
Node 모의 ZEP 테스트 43개를 통과했습니다. 부족 안내의 채팅 미출력/현재 수/남은 수/중복 창 방지/다른 이용자 및 오래된 창 메시지 차단/조건 충족 후 응모/초기화/퇴장 정리를 포함합니다. 기존 수집/관리자/카드 기능도 확인했습니다.

Chromium 1280×800, 390×700, 320×568, 568×280에서 모의 하단 툴바 80px와 겹치지 않는 닫기 버튼, 실제 터치, 카드 바로 아래 버튼 간격, 새 일러스트 바이트와 전체 표시를 확인했습니다. 실제 ZEP 맵에서도 업데이트 후 응모 데스크와 카드 표시, 닫기 후 이동, 저장 유지를 확인하세요.
