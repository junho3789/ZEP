# ZEP NPC · API 없는 대화 버전 v2.0.2

외부 AI API, API 키, 별도 서버 없이 **ZEP Script 안에서만** 동작합니다. 캐릭터별 대사·키워드·후속 답변을 관리자가 ZEP 내 에디터에서 편집합니다. 생성형 AI는 아니며 등록한 규칙과 대사로 대화합니다.

**[v2.0.2 적용·업데이트 도구 다운로드](https://github.com/junho3789/ZEP/raw/refs/heads/main/ai-npc-app/dist/zep-npc-offline-builder-v2.0.2.zip)** · [샘플 캐릭터로 기능 테스트](https://github.com/junho3789/ZEP/raw/refs/heads/main/ai-npc-app/dist/zep-npc-offline-v2.0.2-sample.zip)

## 현재 자리에 직접 배치하기 — v2.0.2

`!npc-here` 후에도 생성 수가 0/2이고 빈 타일이 없다는 오류가 나오면, 관리자가 현재 서 있는 타일에 NPC 하나를 직접 배치할 수 있습니다. 주변 빈 타일을 찾는 과정을 사용하지 않습니다.

1. 위 **v2.0.2 적용·업데이트 도구**에서 기존 앱 ZIP을 불러와 새 앱 ZIP을 만듭니다. 기존 이미지와 걷기 프레임을 유지합니다.
2. 같은 ZEP 앱에 새 ZIP을 적용하고 맵에 재접속합니다.
3. `!npc-place moa`를 입력합니다. 모아가 현재 유저 위치에 겹쳐 생성될 수 있으므로 두세 타일 이동해 확인하세요.
4. 다른 빈 위치로 이동한 후 `!npc-place sage`를 입력하면 서가도 그곳에 배치됩니다.
5. `!npc-status`에서 버전이 2.0.2인지, 생성 수와 좌표가 나오는지 확인합니다. 주변 3×3 타일의 제외 이유도 표시합니다.

이 명령은 관리자·소유자만 사용합니다. 통행 불가 타일과 다른 NPC가 이미 있는 타일은 거부하지만, 유저가 서 있는 타일의 장식 그림 때문에 배치를 막지는 않습니다. 기존 맵 오브젝트를 삭제하거나 교체하지 않고 별도의 키 오브젝트를 겹쳐 놓습니다. 이미 생성한 NPC에 다시 명령하면 중복 생성하지 않고 이동합니다. 직접 지정한 위치와 주변 배회 영역은 현재 실행 동안만 유지됩니다.

진단의 `현재 타일`은 유저가 서 있는 타일입니다. 그 타일이 비어 있어도 자동 빈 타일 탐색은 유저가 있는 자리를 제외하므로, 주변까지 모두 막힌 것으로 판정하면 0/2가 될 수 있습니다. 실제 사용자 맵에서 주변 타일들이 제외되는 정확한 이유는 새 `NPC 주변 판정` 출력으로 구분합니다. 이 버전의 직접 배치는 그 탐색 결과와 독립적으로 동작합니다. 배회는 그림의 유무만으로 통행을 막지 않고 `moveObjectWithKey(..., true)`의 ZEP 경로 검사를 사용합니다. 명시적인 통행 불가 타일과 다른 유저·NPC가 있는 타일은 계속 피합니다.

## 캐릭터가 보이지 않을 때 / v2.0.0 업데이트

v2.0.0에는 배회 영역이 작은 맵을 벗어나거나 시작 타일이 막혀 있으면 초기화가 중단되는 코드가 있었습니다. v2.0.2에서는 맵 준비 후 NPC를 생성하고, 맵 안으로 배회 영역을 조정하며, 주변의 빈 시작 타일을 검색합니다. 한 NPC의 실패로 다른 NPC 생성이나 에디터가 중단되지 않도록 분리했습니다. 실제 사용자 맵에서 발생한 정확한 원인은 아래 진단 결과로 확인해야 합니다.

1. 위의 **v2.0.2 업데이트 도구**를 내려받아 압축을 풀고 HTML을 엽니다.
2. 첫 번째 **기존 앱 ZIP을 수정판으로 업데이트**에서, ZEP에 올렸던 앱 ZIP을 선택합니다. 원본 PNG 적용 도구로 만든 ZIP이면 이미지와 방향 프레임을 자동으로 불러옵니다. 도구 ZIP 자체를 선택하면 안 됩니다.
3. **ZEP 앱 ZIP 만들기**를 눌러 `zep-npc-offline-v2.0.2.zip`을 받고 기존 앱의 스크립트를 이 ZIP으로 교체합니다. 새로 접속해 적용하세요.
4. 관리자 계정으로 빈 공간에 서서 **`!npc-here`**를 입력하면 NPC를 근처에 배치하고 주변을 새 배회 영역으로 사용합니다. 이 위치 변경은 현재 앱 실행 동안만 유지합니다.
5. **`!npc-status`**로 버전, 맵 크기, 생성 수, NPC 좌표, 이미지 프레임 크기, 실패 이유를 확인합니다. 생성 수가 2/2인데 보이지 않으면 `!npc-here`로 가까이 옮긴 뒤 이미지·프레임 설정을 확인하세요.

`!npc-admin`이 열리면 앱과 위젯은 실행되고 있다는 뜻입니다. `!npc-status`도 아무 반응이 없다면 구버전이 남아 있는지, 일반 앱의 스크립트 ZIP이 적용되었는지 확인하세요. 이미지·프레임 외에 이전 ZIP의 코드 수정 내용은 자동으로 가져오지 않습니다. 에디터에 저장한 대사 설정은 같은 앱을 업데이트하는 경우 기존 App storage에 유지됩니다.

> 채팅에 첨부된 이미지1은 현재 실행 환경에서 원본 파일 바이트를 제공받지 못해 저장소에 직접 넣지 못했습니다. 샘플 ZIP의 이미지는 이전 테스트용 캐릭터입니다. 이미지1을 그대로 적용하려면 위의 도구에서 PC에 있는 원본 PNG를 선택하세요. 원본의 픽셀·투명도는 변경하지 않고 ZIP에 그대로 포함합니다. 이미지를 다시 그리거나 생성하지 않습니다.

## 이미지1로 앱 ZIP 만들기

1. **원본 PNG 적용 도구** ZIP을 다운로드하고 압축을 풉니다.
2. `zep-npc-offline-builder.html`을 Chrome 또는 Edge로 엽니다. GitHub의 파일 미리보기 화면에서는 실행되지 않으니 다운로드 후 여세요.
3. PC에 있는 캐릭터 원본 PNG를 선택합니다. 파일은 브라우저 밖으로 전송되지 않습니다.
4. 프레임 너비·높이를 입력하고 **프레임 나누기**를 누릅니다. 기본값은 48×64px입니다. 실제 원본에 맞게 조정하세요.
5. 방향을 아래·왼쪽·오른쪽·위로 바꿔 가며, 각 방향의 걷기 프레임을 재생할 순서대로 클릭합니다. 옆의 미리보기로 확인하세요. 첫 번째 선택 프레임이 정지 이미지로도 사용됩니다.
6. **ZEP 앱 ZIP 만들기**를 누르면 `zep-npc-offline-v2.0.2.zip`을 다운로드합니다.
7. ZEP Script 개발자 화면에서 새 **일반 앱(Normal App)**에 이 ZIP을 업로드하고 맵에 설치합니다.

도구는 전체 앱 소스를 포함한 단일 HTML입니다. 외부 서비스·라이브러리를 다운로드하지 않습니다. ZIP에는 `main.js`, `chat.html`, `editor.html`, 선택한 원본 `npc.png`가 들어갑니다. PNG 자체를 자르거나 늘리거나 재인코딩하지 않으며, 프레임 정보만 앱 코드에 설정합니다. 원본 프레임 방향은 자동 추측하지 않으므로 직접 확인하고 선택해야 합니다.

## 제공 기능

| 상황 | 동작 |
|---|---|
| 주변에 유저가 없음 | 설정 구역에서 2~5타일 걷기와 0.5~2초 쉬기를 반복 |
| 유저가 2타일 이내 접근 | 이동을 멈추고 대화 대기 |
| 가까이에서 F키 또는 `!npc` | 가장 가까운 NPC의 개인 대화창 열기 |
| 유저가 4타일 초과로 이동 | 그 유저의 대화창 닫기 |
| 주변 유저가 모두 4타일 초과로 이동 | 배회 재개 |
| 여러 유저와 대화 | 유저·NPC별로 대화 상태와 기록 분리 |
| 관리자가 설정 저장 | 새 이름·대사 적용, 해당 NPC의 기존 대화창과 맥락 초기화 |

거리는 대각선도 한 타일로 계산합니다. 정지한 뒤 유저가 3~4타일에 있을 때에는 대기 상태를 유지합니다. 모바일에서는 NPC 방향을 보고 펀치/상호작용 버튼을 사용하거나 채팅에 `!npc`를 입력합니다.

자동 생성 위치를 찾을 때는 벽·일반/상단 오브젝트 그림이 있는 타일을 보수적으로 피합니다. 생성 후 이동은 ZEP의 실제 경로 검사에 맡기며 통행 불가 타일과 유저·NPC를 추가로 피합니다. 맵 편집기로 빈 통로를 배회 구역으로 지정하세요. 기본 시작 좌표는 모아 `(8,8)`, 서가 `(12,8)`이며 배회 구역은 `x=3~16`, `y=3~16`입니다. 작은 맵은 실제 크기로 영역을 줄입니다. 그 영역에 빈 타일이 하나도 없으면 생성 실패를 진단 명령으로 안내하며, 관리자 `!npc-here`로 빈 공간 근처에 배치할 수 있습니다.

## 관리자 에디터

ZEP 맵 소유자·관리자 계정으로 채팅에 **`!npc-admin`**을 입력합니다. 관리자에게는 대화창 안에도 **캐릭터 편집** 버튼이 보입니다. 별도의 로그인 키나 API 키는 없습니다. ZEP 서버가 제공하는 읽기 전용 `player.role`의 관리자(3000)·소유자(3001) 권한을 검사합니다. 일반 유저의 위젯 메시지로 권한을 부여하지 않습니다.

편집 항목:

- **이름·성격 소개·배경/공간 안내**
- **말투 기본값**: 친근한 반말, 다정한 존댓말, 발랄한 말투, 차분한 존댓말
- **인사말·모르는 질문 답변**: 여러 후보를 작성하면 반복을 줄여 선택
- **주제별 대화**: 키워드, 기본 답변, 후속 답변, 동의·거절 답변

말투를 선택하고 **기본 대사 적용**을 누르면 기본 주제·인사말·모르는 질문 답변이 그 말투로 바뀝니다. 직접 추가한 주제는 유지합니다. 자유롭게 쓴 성격 설명만으로 새 대사가 생성되지는 않습니다. 사용자 정의 주제는 해당 캐릭터의 말투로 대사를 직접 작성하세요.

대사에서는 `{name}` 캐릭터 이름, `{player}` 유저 이름, `{personality}` 성격 소개, `{background}` 공간 안내를 사용할 수 있습니다. 이 치환은 한 번만 수행하며 입력 내용을 코드로 실행하지 않습니다.

저장은 이 앱의 **ZEP App storage**에 기록합니다. 관련 없는 기존 저장 항목은 보존하고, 저장 후 다시 읽어 확인합니다. 다른 편집자가 먼저 저장한 설정은 버전 충돌로 알립니다. 다른 맵에서 같은 앱을 동시에 편집하는 경우 ZEP storage API가 원자적 트랜잭션을 제공하지 않으므로 한 관리 맵에서 순차적으로 편집하세요. 다른 맵은 앱을 다시 시작하거나 에디터의 다시 불러오기를 사용해야 최신 설정이 반영됩니다.

## 대화 규칙 작성 예시

| 항목 | 예시 |
|---|---|
| 주제 이름 | 도서관 안내 |
| 키워드 | 도서관, 책빌리기, 대출안내 |
| 기본 답변 | 도서관은 광장 북쪽에 있어요. |
| 후속 답변 | 파란 문으로 들어오시면 돼요. |

`도서관 어디야?`에 기본 답변을 하고, 이어서 `더 알려줘`라고 하면 후속 답변을 합니다. 키워드는 공백·문장부호를 제외하고 2자 이상입니다. 일치하는 키워드가 여러 개면 더 긴 키워드를 우선합니다. 영어는 단어 경계를 검사하므로 `hi`가 `this`에 잘못 반응하지 않습니다.

동의·거절 분기는 기본 답변이 질문인 주제에서 사용합니다. 두 답변을 모두 등록해야 합니다.

```
유저: 뭐 하고 있어?
모아: 잠깐 산책하고 있었어. 같이 걸을래?
유저: 좋아
모아: 좋아! 이야기 끝나고 주변을 천천히 둘러보자.
```

이 분기는 직전 질문에만 적용하며 다른 주제로 넘어가면 종료합니다. NPC가 유저를 따라다니는 기능은 포함하지 않습니다. 모르는 질문에는 등록한 안내 대사로 응답하며, 새로운 사실을 만들어내거나 외부 정보를 조회하지 않습니다.

## 소스 수정·빌드

Python 3와 Node.js 22 이상이 필요하며 설치할 외부 패키지는 없습니다.

```sh
python3 ai-npc-app/build.py
```

이 명령은 테스트를 실행한 뒤 `dist`에 원본 PNG 적용기 ZIP/HTML과 샘플 ZIP을 만듭니다. 적용기는 현재 `zep/config.js`의 NPC 목록과 좌표, 최신 대화 코드를 포함합니다. NPC 추가나 이동 구역 변경은 `zep/config.js`를 편집한 뒤 도구를 다시 빌드하세요. 같은 ID를 중복해서 쓰지 마세요.

`zep/npc.png`는 샘플용입니다. 이미지1 원본을 환경에 전달받지 못한 상태이므로 이 파일을 이미지1이라고 표시하지 않습니다. 적용기에서 선택한 원본을 최종 ZIP의 `npc.png`로 사용합니다.
